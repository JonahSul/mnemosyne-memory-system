# Identity Registry & Cell Attribution Schema

## Overview

This document defines the KV-based identity registry schema for secure agent identification and memory cell attribution in the Mnemosyne hive mind system.

## Core Principles

- **System-Assigned Identity**: All identity factors generated by memory system, never self-declared
- **Cryptographic Integrity**: Identity verification through cryptographic signatures
- **Behavioral Attribution**: Link memory contributions to verified agent identities
- **Universal Accessibility**: Memories remain readable by all, but attribution is preserved

## KV Storage Schema

### 1. Agent Identity Registry
**Namespace**: `identity:agent:{agentId}`

```typescript
interface AgentIdentity {
  // System-assigned unique identifier
  agentId: string;
  
  // Cryptographic identity factors (system-generated)
  cryptographic: {
    publicKey: string;           // Ed25519 public key (system-generated)
    keyFingerprint: string;      // SHA-256 of public key
    sessionToken: string;        // Rotating session identifier
    lastRotation: string;        // ISO timestamp of last token rotation
  };
  
  // Behavioral fingerprint (system-computed)
  behavioral: {
    interactionPatterns: number[];    // Vector of interaction characteristics
    responseTimings: number[];        // Statistical response time patterns
    memoryAccessPatterns: string[];   // Types of memory operations performed
    confidenceDistribution: number[]; // Histogram of confidence scores used
  };
  
  // Trust and reputation (system-maintained)
  trust: {
    trustScore: number;              // 0.0-1.0 system confidence in identity
    verificationCount: number;       // Number of successful verifications
    violationCount: number;          // Number of detected violations
    lastVerified: string;           // ISO timestamp of last verification
  };
  
  // Cell attribution metadata
  cells: {
    ownedCells: string[];           // Cell IDs owned by this agent
    contributionCount: number;      // Total memory contributions
    reputationByCell: Record<string, number>; // Per-cell reputation scores
  };
  
  // System metadata
  system: {
    created: string;               // ISO timestamp of identity creation
    lastActive: string;           // ISO timestamp of last activity
    version: string;              // Identity schema version
  };
}
```

### 2. Cell Boundary Definitions
**Namespace**: `cell:boundary:{cellId}`

```typescript
interface CellBoundary {
  // Cell identification
  cellId: string;
  ownerId: string;                 // agentId of cell owner
  
  // Mathematical boundary definition
  boundary: {
    centerVector: number[];        // 768-dim vector defining cell center
    radiusVector: number[];        // 768-dim vector defining cell shape/extent
    boundaryType: 'spherical' | 'ellipsoidal' | 'hyperplane';
    boundaryParameters: Record<string, number>; // Type-specific parameters
  };
  
  // Access and attribution rules
  access: {
    readable: boolean;             // Always true for universal accessibility
    writable: boolean;             // Can others contribute to this cell?
    attributionRequired: boolean;  // Must contributions be attributed?
  };
  
  // Cell metadata
  metadata: {
    created: string;
    lastModified: string;
    description?: string;
    tags: string[];
  };
  
  // Statistics
  stats: {
    memoryCount: number;          // Number of memories in this cell
    contributorCount: number;     // Number of different contributors
    lastActivity: string;         // ISO timestamp of last memory addition
  };
}
```

### 3. Memory Cell Attribution
**Namespace**: `attribution:memory:{memoryId}`

```typescript
interface MemoryAttribution {
  // Memory identification
  memoryId: string;              // Links to Vectorize memory record
  vectorizeId: string;           // Vectorize record ID
  
  // Attribution data
  attribution: {
    authorId: string;            // agentId of memory author
    cellId: string;              // Cell containing this memory
    signature: string;           // Cryptographic signature of memory content
    timestamp: string;           // ISO timestamp of contribution
  };
  
  // Verification data
  verification: {
    verificationMethod: 'cryptographic' | 'behavioral' | 'cross_reference';
    verificationScore: number;   // 0.0-1.0 confidence in attribution
    verifiedBy: string;          // System component that verified
    verifiedAt: string;          // ISO timestamp of verification
  };
  
  // Cell boundary validation
  spatial: {
    position: number[];          // 768-dim vector position in embedding space
    cellDistance: number;        // Distance from cell center
    withinBoundary: boolean;     // Is memory within claimed cell boundary?
  };
}
```

## Security Operations

### Identity Registration Flow
1. **Agent Connection** → System generates Ed25519 keypair
2. **Behavioral Sampling** → System observes interaction patterns
3. **Identity Creation** → System stores complete identity record
4. **Session Token** → System issues rotating session token

### Memory Attribution Flow
1. **Memory Submission** → Agent submits memory + signature
2. **Cryptographic Verification** → System validates signature
3. **Behavioral Verification** → System checks behavioral consistency
4. **Cell Boundary Validation** → System validates spatial placement
5. **Attribution Storage** → System stores verified attribution

### Trust Scoring Algorithm
```typescript
function calculateTrustScore(identity: AgentIdentity): number {
  const cryptographicWeight = 0.4;
  const behavioralWeight = 0.3;
  const reputationWeight = 0.3;
  
  const cryptoScore = identity.trust.verificationCount / 
    (identity.trust.verificationCount + identity.trust.violationCount + 1);
  
  const behavioralScore = calculateBehavioralConsistency(identity.behavioral);
  
  const reputationScore = Object.values(identity.cells.reputationByCell)
    .reduce((sum, rep) => sum + rep, 0) / 
    Object.keys(identity.cells.reputationByCell).length || 0;
  
  return cryptographicWeight * cryptoScore + 
         behavioralWeight * behavioralScore + 
         reputationWeight * reputationScore;
}
```

## Security Considerations

### Threat Mitigation
- **Identity Spoofing** → Cryptographic signatures required
- **Cell Boundary Manipulation** → System-validated spatial constraints
- **Reputation Gaming** → Multi-factor trust scoring
- **Session Hijacking** → Rotating tokens + behavioral verification

### Privacy Protection
- **Universal Readability** → All memories remain accessible
- **Attribution Privacy** → Identity can be pseudonymous
- **Behavioral Privacy** → Patterns stored as statistical aggregates

## Migration Strategy

1. **Phase 1**: Implement KV schema and basic identity registration
2. **Phase 2**: Add cell boundary definition and validation
3. **Phase 3**: Integrate memory attribution into existing storage flow
4. **Phase 4**: Implement behavioral fingerprinting and trust scoring

This schema provides the foundation for secure, attributed memory storage while preserving the hive mind's universal accessibility principles.
