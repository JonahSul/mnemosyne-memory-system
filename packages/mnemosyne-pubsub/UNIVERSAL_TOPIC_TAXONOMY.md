# Universal Topic Taxonomy

A foundational set of 25 topics that can be variously combined to describe any concept, system, or phenomenon in reality. Optimized for coding, software architecture, and data domains.

## The 25 Universal Topics

### 1. **Structure**
The organization, composition, and arrangement of components. How parts relate to wholes.

*Examples:* Data structures, system architecture, molecular composition, organizational hierarchies, code modules, database schemas, class hierarchies, network topologies

*Combinations:*
- Structure + Transformation = Refactoring, evolution, morphing
- Structure + Flow = Architecture patterns, data pipelines
- Structure + State = Configuration, schema design

---

### 2. **Flow**
Movement, transfer, and progression through time or space. Sequences and transitions.

*Examples:* Control flow, data flow, execution paths, pipelines, streams, event propagation, state machines, workflows, processes

*Combinations:*
- Flow + Control = Orchestration, workflow engines
- Flow + Time = Event streams, temporal sequences
- Flow + Transformation = Data pipelines, ETL

---

### 3. **State**
Current condition, status, or snapshot at a point in time. What exists now.

*Examples:* Application state, database records, memory contents, variable values, system status, configuration, snapshots, checkpoints

*Combinations:*
- State + Time = History, state machines, versioning
- State + Change = Mutations, updates, transitions
- State + Boundary = Encapsulation, scope

---

### 4. **Transformation**
Change, conversion, and modification from one form to another.

*Examples:* Data transformation, compilation, encoding/decoding, mapping, projection, aggregation, normalization, mutation, evolution

*Combinations:*
- Transformation + Invariance = Type safety, conservation laws
- Transformation + Composition = Function chains, middleware
- Transformation + Reversibility = Serialization/deserialization

---

### 5. **Pattern**
Recurring regularities, templates, and recognizable structures across instances.

*Examples:* Design patterns, algorithms, regular expressions, templates, motifs, idioms, anti-patterns, architectural patterns

*Combinations:*
- Pattern + Recognition = Parsing, pattern matching, ML
- Pattern + Abstraction = Generics, metaprogramming
- Pattern + Composition = Composite patterns, frameworks

---

### 6. **Abstraction**
Simplification through hiding details and exposing essential concepts.

*Examples:* Interfaces, APIs, abstract classes, higher-order functions, protocols, encapsulation, virtualization, models

*Combinations:*
- Abstraction + Boundary = Interfaces, contracts
- Abstraction + Composition = Layers, facades
- Abstraction + Leakage = Implementation details, side effects

---

### 7. **Identity**
Uniqueness, naming, and persistent recognition across time and context.

*Examples:* Primary keys, UUIDs, variable names, memory addresses, DNS names, namespaces, object identity, entity IDs

*Combinations:*
- Identity + Equality = Comparison semantics
- Identity + Reference = Pointers, foreign keys
- Identity + Namespace = Scoping, qualification

---

### 8. **Relationship**
Connections, associations, and dependencies between entities.

*Examples:* Foreign keys, references, edges in graphs, associations, dependencies, inheritance, composition, links, bindings

*Combinations:*
- Relationship + Cardinality = One-to-many, many-to-many
- Relationship + Direction = Bidirectional, unidirectional
- Relationship + Strength = Strong/weak references, coupling

---

### 9. **Boundary**
Limits, interfaces, and separation between regions or domains.

*Examples:* Module boundaries, API surfaces, network boundaries, process boundaries, trust boundaries, scope, namespaces, contexts

*Combinations:*
- Boundary + Crossing = Marshalling, RPC, syscalls
- Boundary + Protection = Access control, sandboxing
- Boundary + Permeability = Public/private, visibility

---

### 10. **Composition**
Building complex things from simpler parts. Combination and aggregation.

*Examples:* Object composition, function composition, service composition, microservices, modules, components, mixins, plugins

*Combinations:*
- Composition + Reusability = Components, libraries
- Composition + Hierarchy = Tree structures, nesting
- Composition + Multiplicity = Collections, aggregates

---

### 11. **Time**
Temporal ordering, duration, and sequencing of events.

*Examples:* Timestamps, event ordering, causality, scheduling, TTL, temporal databases, versioning, time-series data, clocks

*Combinations:*
- Time + Ordering = Causality, happens-before
- Time + Measurement = Performance metrics, latency
- Time + Synchronization = Distributed consensus, clocks

---

### 12. **Space**
Physical or logical location, proximity, and spatial relationships.

*Examples:* Memory layout, data locality, geographic distribution, network topology, coordinate systems, address spaces, regions

*Combinations:*
- Space + Partitioning = Sharding, distribution
- Space + Proximity = Locality, caching
- Space + Dimensionality = Vector spaces, coordinates

---

### 13. **Scale**
Magnitude, size, and capacity considerations from small to large.

*Examples:* Scalability, big O notation, data volume, throughput, concurrency, cardinality, dimensionality, problem size

*Combinations:*
- Scale + Performance = Optimization, efficiency
- Scale + Distribution = Horizontal scaling, sharding
- Scale + Complexity = Algorithmic complexity

---

### 14. **Constraint**
Limitations, requirements, and invariants that must be maintained.

*Examples:* Type constraints, business rules, database constraints, resource limits, preconditions, invariants, contracts, validation

*Combinations:*
- Constraint + Satisfaction = Solvers, validation
- Constraint + Violation = Errors, exceptions
- Constraint + Propagation = Type inference, constraints

---

### 15. **Uncertainty**
Ambiguity, probability, and incomplete information.

*Examples:* Error handling, probabilistic data structures, eventual consistency, race conditions, non-determinism, fuzzy logic, ML predictions

*Combinations:*
- Uncertainty + Resolution = Error handling, fallbacks
- Uncertainty + Quantification = Probability, confidence
- Uncertainty + Propagation = Error propagation

---

### 16. **Control**
Direction, governance, and decision-making mechanisms.

*Examples:* Control flow, access control, authorization, conditional logic, orchestration, policy enforcement, rate limiting, governance

*Combinations:*
- Control + Flow = Branching, loops, conditionals
- Control + Delegation = Authorization, proxies
- Control + Inversion = IoC, dependency injection

---

### 17. **Concurrency**
Simultaneous execution, parallelism, and coordination.

*Examples:* Threads, processes, async/await, locks, semaphores, race conditions, parallel algorithms, concurrent data structures

*Combinations:*
- Concurrency + Synchronization = Locks, barriers
- Concurrency + Isolation = Transactions, STM
- Concurrency + Communication = Message passing, channels

---

### 18. **Persistence**
Long-term storage and durability beyond process lifetime.

*Examples:* Databases, file systems, logs, caches, snapshots, backups, durable storage, serialization, archival

*Combinations:*
- Persistence + Consistency = ACID, durability
- Persistence + Retrieval = Indexing, queries
- Persistence + Layering = Cache hierarchies

---

### 19. **Communication**
Information exchange and message passing between entities.

*Examples:* APIs, protocols, messages, events, RPC, HTTP, sockets, pub/sub, IPC, network communication, signals

*Combinations:*
- Communication + Reliability = Acknowledgments, retries
- Communication + Pattern = Request/response, pub/sub
- Communication + Medium = Network, shared memory

---

### 20. **Semantics**
Meaning, interpretation, and intended behavior.

*Examples:* Language semantics, data semantics, business logic, domain models, ontologies, type semantics, behavioral contracts

*Combinations:*
- Semantics + Syntax = Language design, parsing
- Semantics + Verification = Type checking, testing
- Semantics + Formalization = Specifications, proofs

---

### 21. **Performance**
Efficiency, speed, and resource utilization.

*Examples:* Time complexity, space complexity, throughput, latency, optimization, profiling, benchmarking, resource usage

*Combinations:*
- Performance + Measurement = Profiling, metrics
- Performance + Trade-offs = Time vs space, CAP theorem
- Performance + Optimization = Caching, indexing

---

### 22. **Reliability**
Dependability, fault tolerance, and correctness guarantees.

*Examples:* Error handling, redundancy, replication, testing, fault tolerance, availability, correctness, consistency, recovery

*Combinations:*
- Reliability + Failure = Fault tolerance, recovery
- Reliability + Verification = Testing, formal methods
- Reliability + Redundancy = Replication, backups

---

### 23. **Security**
Protection, confidentiality, and integrity of systems and data.

*Examples:* Authentication, authorization, encryption, validation, sanitization, access control, trust boundaries, threat models

*Combinations:*
- Security + Identity = Authentication, authorization
- Security + Boundary = Trust boundaries, sandboxing
- Security + Information = Encryption, secrets management

---

### 24. **Observation**
Monitoring, introspection, and understanding system behavior.

*Examples:* Logging, metrics, tracing, debugging, profiling, monitoring, telemetry, observability, instrumentation

*Combinations:*
- Observation + Time = Tracing, time-series metrics
- Observation + Causality = Distributed tracing
- Observation + Aggregation = Dashboards, analytics

---

### 25. **Intent**
Purpose, goals, and desired outcomes driving design and behavior.

*Examples:* Requirements, specifications, business logic, user stories, design goals, optimization objectives, invariants, contracts

*Combinations:*
- Intent + Implementation = Code, architecture
- Intent + Verification = Testing, validation
- Intent + Documentation = Specifications, comments

## Usage Guidelines

### For Tagging and Classification
Tag content with 2-5 topics that best capture its essence. The combination defines the concept space.

### For Search and Retrieval
Query by topic combinations to find related concepts:
- "Structure + Flow" → architectures, pipelines
- "State + Time" → versioning, history
- "Scale + Reliability" → distributed systems

### For Relationship Discovery
Topics create a semantic space where distance indicates conceptual similarity:
- Close: State ↔ Persistence
- Close: Flow ↔ Transformation
- Close: Boundary ↔ Security

### For Knowledge Organization
Build hierarchies and networks:
- Root concepts (1-2 topics)
- Detailed concepts (3-4 topics)
- Specific implementations (4-5+ topics)

### For AI/ML Applications
- **Embedding space dimensions**: Each topic can be a dimension
- **Topic modeling**: LDA over this vocabulary
- **Semantic similarity**: Cosine similarity in topic space
- **Concept drift**: Topic distribution changes over time

## Implementation in Mnemosyne PubSub

```typescript
import { TopicTracker, EventBus } from '@mnemosyne/pubsub';

const universalTopics = [
  'structure', 'flow', 'state', 'transformation', 'pattern',
  'abstraction', 'identity', 'relationship', 'boundary', 'composition',
  'time', 'space', 'scale', 'constraint', 'uncertainty',
  'control', 'concurrency', 'persistence', 'communication', 'semantics',
  'performance', 'reliability', 'security', 'observation', 'intent'
];

const eventBus = new InMemoryEventBus();
const topicTracker = new TopicTracker(eventBus);

// Tag a memory with topic combinations
await eventBus.publish({
  type: EventType.MEMORY_STORED,
  payload: {
    memoryId: 'mem-001',
    content: 'Implemented distributed caching layer',
    tags: ['performance', 'persistence', 'scale', 'distribution'],
    // This memory is about: Performance + Persistence + Scale + Distribution
  }
});

// Subscribe to specific topic combinations
topicTracker.subscribeToTopics('client-1', 
  ['performance', 'scale'], 
  {
    callback: (event) => {
      // Get notified of all performance + scale related changes
    }
  }
);
```
